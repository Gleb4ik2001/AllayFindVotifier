# AllayFind Paper 1.0.0

Получатель голосов AllayFind и выдача наград для **Paper 1.21.x**, Java 21+.
Собран против Paper API 1.21 без NMS. Целевая платформа — обычный Paper:
Folia, Fabric, PocketMine и Nukkit этой сборкой не поддерживаются.
Компиляция против API не заменяет проверку на конкретной версии сервера.
Основа проекта: [документация Paper](https://docs.papermc.io/paper/dev/project-setup/).

NuVotifier и дополнительный TCP-порт не нужны. Встроены HTTP-клиент, SQLite и
выполнение локально заданных команд консоли. На сайте выбрать **API AllayFind**.

## Установка

1. Скопировать `target/AllayFind-Paper-1.0.0.jar` в `plugins/` тестового Paper.
2. Запустить сервер. Создастся `plugins/AllayFind/config.yml`; с пустым ключом
   плагин отключится и попросит проверить конфигурацию.
3. На сайте: «Мои серверы → Получение голосов → API AllayFind → Создать ключ».
   Если ранее выбран Votifier, сначала завершить доставку его ожидающих голосов.
4. Заполнить конфигурацию:

   ```yaml
   site-url: "https://allayfind.example"
   server-id: 123
   api-token: "ключ-из-кабинета"
   edition: "java"
   poll-seconds: 30
   allow-local-http: false
   reward-commands:
     - "give {player} minecraft:diamond 1"
   ```

   `site-url` — адрес сайта без пути `/api/...`. `server-id` — ID карточки.
   Ключ хранится в локальном конфиге: не публикуйте этот файл и не отправляйте
   его в чат. Для разработки на том же компьютере разрешён
   `http://127.0.0.1:8000` при `allow-local-http: true`. Другие HTTP-адреса запрещены.
5. Полностью перезапустить Paper. Не использовать `/reload`.
6. Выполнить `/allayfind status`, затем проголосовать на сайте под игровым ником.
   Для выдачи награды игрок должен находиться онлайн. Получение/выдача обычно
   происходит за один интервал опроса; после входа также дождитесь следующего опроса.

## Команды

Требуют `allayfind.admin` (по умолчанию OP). Доступны из консоли.

| Команда | Назначение |
| --- | --- |
| `/allayfind status` | Состояние API и количество локальных событий по статусам |
| `/allayfind poll` | Немедленно запросить реальные голоса и обработать очередь |
| `/allayfind queue` | Показать первые 20 незавершённых событий и их UUID |
| `/allayfind retry UUID` | Вернуть `uncertain` в очередь; может повторить уже выданную награду |
| `/allayfind confirm UUID` | Отметить `uncertain` как выполненное после проверки логов |

`poll` не создаёт тестовый голос. Лимит сайта 24 часа сохраняется.
HTTP 401 обычно означает неверный ключ, неверный ID, отключённую интеграцию,
неподтверждённый сервер или выбранный режим Votifier вместо API.

## Награды и надёжность

- HTTP и SQLite выполняются на отдельном последовательном worker-потоке.
  Игроки и команды Bukkit используются только в основном потоке сервера.
- Полученные голоса сначала сохраняются в `votes.db` с уникальным ID,
  затем подтверждаются сайту. Повторная доставка не добавляет вторую награду.
- Офлайн-награды хранятся локально до появления игрока с совпадающим ником
  без учёта регистра. Это не подтверждение владения Minecraft-аккаунтом.
- Список команд фиксируется при первом сохранении голоса. Изменение config.yml
  влияет на новые события после перезапуска, а не на ранее сохранённые награды.
- Плейсхолдеры: `{player}` — фактический ник онлайн-игрока, `{uuid}` — его UUID,
  `{vote_id}` — уникальный ID голоса. Команды без начального `/`, по одной на строку.
- Перед командами состояние `executing` записывается на диск. При аварии оно
  превращается в `uncertain` при следующем запуске. Автоматического повтора нет.
- При отказе команды или исключении дальнейшие команды события не выполняются;
  событие требует ручной проверки. Частично выданные награды автоматически не откатываются.
- `done` означает, что Bukkit принял все команды без исключений. Некоторые команды
  сообщают об ошибке только текстом, поэтому это не доказательство изменения баланса/инвентаря.

Строгой гарантии «ровно один раз» для произвольных команд нет. Для финансовых
или ценных наград нужен идемпотентный обработчик с `{vote_id}` либо транзакционный API.

Не удаляйте `votes.db` ради сброса лимитов: сайт уже мог подтвердить эти события,
и удаление потеряет офлайн-награды. Делайте резервную копию всей папки AllayFind
при остановленном сервере (включая WAL-файлы, если они остались).
Смена сайта/ID/edition с той же БД блокируется. Для другой карточки нужна отдельная
папка данных; прежнюю очередь сначала завершить или сохранить для старого сервера.
Запускайте один получатель на карточку. Прокси-сети и синхронизация нескольких
независимых SQLite-баз в эту версию не входят.

## Bedrock через Geyser

Это плагин Java-сервера. Вводить нужно имя, которое видит Paper после Geyser/Floodgate,
включая префикс точки. Для команд поддержаны буквы ASCII, цифры, `_` и `.`, без пробелов.
Получение голосов отдельной Bedrock-карточки допускает `edition: bedrock`, но
сопоставление XUID/UUID и преобразование Gamertag здесь не реализованы.

## Сборка и проверки

Требуются JDK 21+ и Maven 3.9+. Из папки плагина:

```sh
mvn clean verify
```

Результат: `target/AllayFind-Paper-1.0.0.jar` (SQLite и Gson включены).
Автотесты проверяют HTTP с локальным сервером, авторизацию, отказ от редиректов,
валидацию событий, повторную доставку, восстановление SQLite и обработку команд.
На живом Paper дополнительно проверить загрузку JAR, выдачу алмаза, офлайн-игрока,
перезапуск и недоступность сайта. Использование только стабильного Bukkit API
снижает зависимость от версии Minecraft, но не гарантирует все будущие версии.
